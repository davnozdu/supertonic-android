# Открытые записи для скачиваемого банка · 6 ноября 2026

Запрос: найти записи, которые можно обработать, выложить на наш GitHub и
подкачивать в MyTTS, сохраняя описание лицензии. Это исследование источников
и текущего пути метаданных; клипы пока не скачивались, не прослушивались и
не публиковались. Код приложения не менялся.

## Подходящие условия

- [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/): разрешены
  копирование, обработка и распространение, в том числе коммерческое.
  Авторство сохраняем по пожеланию пользователя, хотя CC0 этого не требует.
- [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/): также разрешает
  распространять и перерабатывать; необходимо сохранить сведения об авторстве,
  ссылку на лицензию, отметить изменения и сохранить предоставленные уведомления.
  Старые версии CC BY проверять отдельно, не переписывать их как 4.0.
- Для первого набора предпочтительна CC0. Пометка royalty-free сама по себе
  не подтверждает право перепубликовать файл как часть банка.

## Исключить из публичного банка без отдельного разрешения

- [Sonniss GDC](https://sonniss.com/gdc-bundle-license/), версия 2.0,
  действует для новых загрузок с 27.08.2026: запрещает перепубликацию звуков
  как библиотеки, в том числе изменённых. Использование в готовом произведении
  и публикация скачиваемого банка — разные случаи.
- [BBC](https://sound-effects.bbcrewind.co.uk/licensing): бесплатные условия
  ограничены личным/образовательным/исследовательским использованием.
- NC/ND и произвольные stock-лицензии не включать в первый набор.

## Сохранение лицензии в нашем конвейере

Предлагаемый путь: исходник + карточка происхождения → обработанный клип → наш
GitHub prerelease → манифест → скачивание нужного варианта по URL с SHA256.
Сохранить прежние сгенерированные варианты; реальные записи добавлять как новые.

На **каждый вариант файла**, а не только вид события, хранить:

- стабильный asset id, название, описание/теги, event kind;
- источник, URL карточки, source id, автора и предоставленную строку credit;
- точный идентификатор и URL лицензии, текст уведомлений и оговорок источника;
- дату проверки, архивную копию карточки и условий для внутреннего учёта;
- SHA256 исходника и результата, длительность, формат;
- список фактически выполненных изменений: вырезка с таймкодами, усиление,
  fade, ресемплинг, AAC-кодирование. Не приписывать обработку до её выполнения.

В релизе: `manifest.json`, читаемый `CREDITS.md`, локальные тексты лицензий
`LICENSES/` и сами клипы/архивы. Кредиты генерировать из тех же карточек, что и
манифест. У разных файлов остаются собственные лицензии; лицензия кода MyTTS
не заменяет их. Для CC BY сохранять предоставленные уведомления и указание
изменений, не добавлять ограничений, несовместимых с исходной лицензией.

При подкачке сохранять карточку в локальном индексе вместе с файлом. Обновление
манифеста, очистка, копирование в книгу, импорт и экспорт должны сохранять
сведения всех остающихся файлов, включая старые версии и собственные клипы.
Книга/экспорт должны получать свои кредиты для реально использованных файлов.
Лицензия и автор должны читаться офлайн, например в разделе «Лицензии звуков».

## Что обнаружено в текущем коде

- `ambience/SoundBank.kt`: `Variant` хранит только file/sha/url, `Entry` —
  file/sha/prompt/variants. Сырой скачанный manifest сохраняется, поэтому
  дополнительные поля в нём могут оставаться, но объектная модель их не передаёт.
- `export()` строит новый manifest из file/key/bytes/sha/prompt/seconds,
  теряя сведения о происхождении; `importZip()` обрабатывает аудио и не переносит
  лицензионные сведения из входного манифеста.
- `tools/sound_bank/pack.py` также не включает автора/лицензию. Это ранний
  сборщик v2, его нельзя принимать за единственный актуальный сборщик v11:
  перед реализацией проверить `bank_gen.py` и `extend_reactions_v11.py`.

Следовательно, добавить credit только на страницу релиза недостаточно.
До публикации первого внешнего набора необходимо провести метаданные через
загрузку, локальное хранение, книги и экспорт/импорт. Проверка должна включать
полный цикл export → import и сохранение credit после обновления банка;
отдельно проверить разные лицензии двух вариантов одного события.

## Уточнение после обсуждения с пользователем

Для CC0 локальный текст лицензии вместе с каждым скачиваемым аудиофайлом
не обязателен. Пользователь предпочитает отдельную публикацию сведений о лицензиях
и подкачку только аудио. Для CC BY 4.0 раздел 3(a)(2) допускает разумный способ
атрибуции через ссылку на ресурс со всеми обязательными сведениями; такую ссылку
нужно явно предоставлять пользователю. Строгая схема выше была предложением
по учёту, а не обязательным условием CC0.

Подготовка реализована отдельным конвейером: `docs/open-bank-pipeline.md`.
