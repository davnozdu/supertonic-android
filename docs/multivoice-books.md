# Голоса персонажей для книг · план и состояние

Начато 8 октября 2026. Документ для продолжения работы любой LLM/разработчиком: что решено, что сделано,
что дальше. Обновлять раздел «Состояние» после каждого этапа.

## Цель

Пользователь выбирает книгу (EPUB), она один раз готовится: персонажи, их формы имён, пол, голоса.
Потом книга читается в Moon+ Reader как обычно, а MyTTS по самому тексту, который присылает читалка,
узнаёт книгу и раздел и читает реплики каждого главного персонажа его голосом. Второстепенные и
нераспознанные — голосом «прочих» своего пола (то есть нынешние мужской/женский голоса мультиголоса),
повествование — голосом автора. Готовые подготовки можно передавать друг другу файлом.

## Решения пользователя (не пересматривать без него)

- Скрипт делает механическую работу (извлечение кандидатов), LLM только сопоставляет. Сопоставление
  «железное»: сомнение — кандидат в «прочие». Скрипт универсальный: никаких списков под конкретную книгу.
- Сборник рассказов: свои персонажи у каждого раздела оглавления; роман — одни на всю книгу.
- LLM: Ollama Cloud, deepseek-v4.1-flash, запросы строго по одному. Размышление по умолчанию ВЫКЛ
  («нужна скорость»); флаг `--think` включает. Ключ API не записывать никуда (только переменная окружения).
- Голоса: модель Silero CIS (29 голосов). Свой голос — тем, кто говорит/часто упоминается; остальные —
  «прочие»; молчащие — «прочие».
- Книга узнаётся не по названию, а по контрольным суммам: SHA-256 файла (уже готовилась ли) и отпечатки
  предложений (узнавание при чтении, Moon+ передаёт только текст). Файлы подготовки — импорт/экспорт.

## Сделано (этап 0): скрипт `tools/characters/book_characters.py`

Подробно — `tools/characters/README.md`. Команды:

- `extract BOOK.epub -o DIR` — pymorphy3 + статистика книги; роман/сборник по оглавлению (верхний уровень
  NCX/nav); кандидаты: цепочки имён (падеж/род согласуются по цепочке), обращения («князь»), семьи (мн. ч.);
  фильтры: нарицательные (чаще со строчной), притяжательные («Зинина» при частой «Зине»), междометия и
  служебные слова, места (Geox). Реплики: имя в именительном в ремарке диалога («— сказал князь»). Род:
  глагол ремарки > отчество > обращение > имя > фамилия. Пишет candidates.json, llm_request.json,
  llm_prompt_*.txt, book_index.json (отпечаток абзаца → раздел; заменить отпечатками предложений, этап 1).
- `llm DIR [--think] [--redo]` — основной запрос + второй запрос «проверка склеек» (same/different/unsure);
  ответы и служебные поля в DIR/answers/ (NAME.json, NAME.verify.json, NAME.meta.json).
- `apply DIR` — проверка: каждый кандидат ровно один раз; к персонажу остаются только подтверждённые
  проверкой и не противоречащие по надёжному роду (глагол/отчество/обращение); обращение без имени —
  только если ≥80 % раз стоит перед именем этого персонажа; имя персонажа только из слов книги.
  Пишет cast.json (casts[] по разделам, characters, other, alias_index, ambiguous, dropped).
- `voices DIR [--voices voices_silero_cis.json]` — свой голос при ≥2 репликах или ≥30 упоминаниях, по полу;
  когда голоса пола кончились — общий с тем, с кем ≤2 общих абзацев; иначе «прочие».
  `voices_silero_cis.json`: 12 мужских (miyau, onaoy, sibday — по слуху пользователя), 17 женских.

## Формат обмена `.mytts-book` (версия 1)

UTF-8 JSON, без текста книги и без примеров из текста (можно передавать, не распространяя книгу):

```json
{
 "format": "mytts-book", "version": 1,
 "book": {"title": "Идиот", "author": "…", "file_sha256": "…", "content_sha256": "…"},
 "scope": "book | section",
 "sections": [{"id": "s1", "title": "Часть первая", "cast": 0}],
 "casts": [{"sections": ["s1", "s2"], "characters": [
   {"id": "myshkin", "name": "Лев Николаевич Мышкин", "gender": "m", "speaker": 420, "mentions": 1510,
    "forms": ["князь", "Лев Николаевич", "Мышкин"], "voice_hint": "ru_alexandr"}], "other": ["Келлер"]}],
 "fingerprint": {"algorithm": "fnv1a64-48", "min_letters": 24},
 "fingerprints": {"s1": ["0f3a…16 hex", "…"]}
}
```

Отпечаток предложения (одинаково в Python и Kotlin, тест-векторы обязательны):
1. Разбить текст на предложения по `(?<=[.!?…])\s+`.
2. Нормализация: нижний регистр, `ё`→`е`, удалить U+0301; оставить только `а-я`, `a-z`, `0-9`;
   первые 48 символов. Если символов меньше 24 — предложение не используется.
3. FNV-1a 64 по кодам символов (UTF-16 code unit): `h = 0xcbf29ce484222325; h ^= code; h *= 0x100000001b3`
   (по модулю 2^64). Хранится как 16 hex; в SQLite — signed 64-bit.

`content_sha256` — SHA-256 конкатенации нормализованных абзацев через `\n` (одинаковый текст из разных
файлов — одна книга). `voice_hint` — рекомендация; на телефоне голоса раздаются заново под установленную
модель (команда voices — алгоритм переносится в Kotlin).

## План интеграции

1. **Скрипт: `export`** → `.mytts-book` (формат выше, отпечатки предложений вместо абзацев). Тест-векторы
   отпечатков в `tools/characters/fingerprint_vectors.json` для Kotlin-теста.
2. **Приложение: библиотека книг.** `books/BookFingerprint.kt` (нормализация+FNV, тест на векторы),
   `books/BookLibrary.kt` (SQLite в no_backup: `books`(id, title, author, file_sha256, content_sha256,
   json, added), `fingerprints`(hash INTEGER PRIMARY KEY … WITHOUT ROWID, book, section); коллизии хешей
   между книгами — строка удаляется (неоднозначна)). Импорт `.mytts-book` через выбор файла, список книг,
   удаление, экспорт («Поделиться»). Экран — в настройках мультиголоса.
3. **Узнавание при чтении.** `books/BookMatcher.kt`: на каждый текст из TTS-клиента (TtsQueueObserver →
   LlmPreparation.submit) и из приложения — отпечатки его предложений → поиск; книга/раздел меняются,
   когда ≥2 совпадений подряд указывают на одно и то же. Состояние по caller (как VoiceRoleContext).
   Без совпадений — прежнее чтение. DiagLog: смена книги/раздела.
4. **Голоса персонажей.** `VoiceRoleText` + необязательный `character`. В запрос ролей (облако
   VoiceRoleProtocol, локальная Gemma — отдельно, позже) добавляется список персонажей текущего раздела
   (id, имя, пол, формы); сегмент реплики может вернуть `speaker` из этого списка, иначе — роль по полу.
   Проверка: speaker должен быть в списке и его пол совпадать с role. Голос: назначение персонажа →
   иначе нынешний голос роли (мужской/женский = «прочие», автор = автор). Голоса персонажам раздаются на
   телефоне из голосов модели, кроме трёх выбранных для ролей. Ключи кэшей ролей/результатов
   (roleCache, LlmResultCache, PCM-кэш) должны включать книгу и раздел.
5. **Проверка на телефоне:** импорт «Идиота», чтение главы в Moon+, точность назначения говорящих
   (выборка реплик вручную), ресурсы. Затем бета.
6. **Позже / открыто:** подготовка книги прямо на телефоне (нужен порт извлечения и морфологии,
   словарь ~10–15 МБ) или только на компьютере; объединение Silero v5.5 и CIS в один пункт.
