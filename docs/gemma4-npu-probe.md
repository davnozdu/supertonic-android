# Gemma 4 E2B на NPU OnePlus CPH2745 — 6 октября 2026

**Реальная генерация на SM8850 / Hexagon V81 подтверждена.** Проверка выполнена
в отдельном APK `com.davnozdu.gemma4.npuprobe`, в ветке `experiment/gemma4-npu`
от `75ae72c6`. Рабочий код озвучки и настройки MyTTS эта ветка не меняет.

## Пакет и воспроизведение

- SDK/QHexRT Maven AAR `0.20.19`; внутренний рантайм сообщает `0.20.18`.
- [Модель](https://huggingface.co/runanywhere/gemma4_e2b_HNPU), revision
  `c3bc94b2d0064ccdc78d993abe2c9fdb038aed3e`, текстовый набор `v81`.
- 10 файлов, **8 251 288 552 байта** хранения (7,68 ГиБ), без аудио/vision.
  SHA256 проверены после скачивания и непосредственно на телефоне перед загрузкой.
- Контекст manifest: 512 токенов. Расширение контекста в этой пробе не проверялось.
- GitHub build [37441453777](https://github.com/davnozdu/supertonic-android/actions/runs/37441453777),
  commit `85de0091`, успешно собран и установлен. APK подписан постоянным
  сертификатом репозитория; прежние временные debug-подписи заменены с сохранением весов.
- Manifest удаляет INTERNET. SDK сообщает backend QHEXRT, deviceKind `npu`,
  deviceName `QHexRT (Qualcomm Hexagon NPU)`, результаты ON_DEVICE.

Код/команды: [tools/gemma-npu-probe](../tools/gemma-npu-probe/README.md).
Нужно зарегистрировать локальный пакет через `importModel`, затем загружать
по model ID. Простое указание абсолютного пути в model_id возвращало
`model not found in registry` ещё до загрузки весов; это исправлено.

## Память

50 выборок с шагом примерно 500–600 мс во время загрузки/генерации/удержания.
Физическая MemTotal телефона: 15 473 740 КиБ (~14,76 ГиБ; паспортные 16 ГБ).

| Счётчик | Результат |
|---|---:|
| Пик PSS процесса | 2 494 833 КиБ = **2,38 ГиБ** |
| Пик RSS процесса | 2 478 648 КиБ = **2,36 ГиБ** |
| Минимальная MemAvailable системы | 3 327 036 КиБ = **3,17 ГиБ** |
| Максимальный VmSwap процесса | 34 524 КиБ = **33,7 МиБ** |
| Global IonTotalUsed до загрузки | 950 476 КиБ |
| Пик Global IonTotalUsed | 3 666 448 КиБ |
| Прирост глобальных DMA-BUF | ~**2,59 ГиБ** |
| PSS после выгрузки | 186 587 КиБ = ~182 МиБ |
| MemAvailable после выгрузки | 5 496 444 КиБ = ~5,24 ГиБ |

**Пакет E2B поместился в память этого телефона в выполненных пробах.**
Это не утверждение, что модель целиком занимает только 2,38 ГиБ: у NPU есть
DMA-BUF, глобальная статистика меняется вместе с другими приложениями.
PSS и IonTotalUsed могут частично учитывать одни и те же буферы, складывать
их как независимые расходы нельзя. PSS/RSS прочитаны разными API в разные
моменты; их пики не являются синхронным снимком. Точная сумма памяти модели
отдельно от системы не установлена.

Память не исчерпывалась, защитный watchdog не сработал. Сам процесс не
вытеснил гигабайты в swap; системный swap уже использовался до пробы.
Одновременное непрерывное чтение MyTTS не запускалось: запас RAM при полной
нагрузке LLM + TTS нужно проверять отдельно при интеграции.

## Скорость и ожидаемая экономия энергии

Ускорение относительно GPU/CPU **не измерено**. Пользователь уточнил:
важна потенциальная экономия энергии даже без роста скорости; измерять заряд
не требуется, достаточно теоретической оценки.

По архитектуре экономия относительно CPU **правдоподобна**: Hexagon содержит
специализированные вычислительные блоки и локальную память для нейросетей.
[Qualcomm описывает это назначение](https://www.qualcomm.com/processors/hexagon).
В длинной пробе CPU time / wall = 0,667 ядра, около **8,3% суммарной мощности
восьми ядер**. Это показатель занятости CPU, а не ватт или батареи: NPU и RAM
тоже потребляют энергию. CPU/GPU baseline с одинаковой задачей не выполнен.

Поэтому ожидаемый вывод: перенос с CPU на NPU имеет смысл как эксперимент
энергосбережения. Процент экономии и преимущество перед GPU не установлены;
дольше работающий, но менее мощный ускоритель не всегда расходует меньше
джоулей на весь запрос. PowerStats HAL телефона не предоставляет energy
channels/consumers; при USB батарейные current_now/power_now были нулевыми.
Питание/зарядку и батарейные настройки не меняли.

## Дальнейшая интеграция

Проверенный путь: QHexRT + E2B `v81` + локальная регистрация каталога + явный
NPU/ON_DEVICE. Это отдельный формат, его нельзя подставить вместо `.litertlm`.
Добавить адаптер локального LLM и ограничение RAM; сохранять проверку ответа
и резервную обработку неподходящих/обрезанных фрагментов. Сначала согласовать
промпт/размер чанков с 512-token context, проверить ударения, ё и неизменность слов.

Изоляция важна: MyTTS уже использует другую версию QNN. Нельзя случайно выбрать
`pickFirst libQnn*.so` и считать две версии согласованными. Проба изолирует их
разными APK/процессами. Для одного APK потребуется согласованный runtime или
отдельная схема загрузки native libs; один android:process не исправляет упаковку.
До этого ветка — проверенный прототип, а не включённый NPU-провайдер MyTTS.

После проверки probe force-stopped, модель выгружена, MyTTS открыт.
USB stay_on возвращён **0**, громкость не меняли. screen_off_timeout=30000
на завершении; этой пробой не изменялся.
