# Персонажи и постоянные голоса: проверка концепта, 8 октября 2026

Проверка выполнена по просьбе пользователя. Функция назначения голосов персонажам
не реализовывалась. Проверялись извлечение имён, пол и сопоставление вариантов
имени; синтез речи не запускался.

## Gemma на NPU

Полный текст разделён на 156 частей до 9000 символов, без потери и повторения
непробельных символов. Выход — компактный список имён, пола и вариантов имени,
лимит 512 выходных токенов на часть.

| Показатель | Результат |
|---|---:|
| Сумма времени 156 запросов | 1252,990 с = **20 мин 53 с** |
| Холодная загрузка модели | 4,532 с дополнительно |
| Медиана запроса | 7,47 с |
| Минимум / максимум | 3,06 / 36,12 с |
| Получены ответы | 156/156 |
| Ответы, разобранные как списки персонажей | 128/156 |
| Медиана decode первых / последних 20 частей | 21,65 / 12,9 токена/с |

128/156 — проверка разбираемости результата, **не точность распознавания**.
Парсер допускает отсутствие массива вариантов имени и строку вместо этого
массива. Остальные 28 ответов требуют исправления или повторного запроса.
Лимит 512 токенов достигнут в одном ответе. Общая дедупликация всех 156 частей,
исправление ответов и разметка каждой реплики в это время не входят.

В конце температура батареи достигла 48,7 °C; ранее thermal status был 3.
Скорость постепенно снижалась. Работа по USB с включённым экраном не позволяет
выводить из этого расход батареи. GPU в этой проверке не измерялся.

Один запрос со всей книгой локальный runtime отверг:
`prompt 392093 + output 64 > 4096`. Это ограничение текущего запуска, а не
заявленной способности семейства Gemma к длинному контексту.

В ответах встречались автор с титульного листа как персонаж, описания и
местоимения как имена. В пробе говорящих фраза «сказал Рогожин Лебедеву»
превратилась в имя «Рогожин Лебедев». Формально правильный JSON такие ошибки
не обнаруживает.

На **точно одинаковых** входах и инструкциях пяти частей из полного локального
прохода получены следующие времена, включая сеть:

| 8991 | 5,060 | 0,658 |
| 8454 | 8,670 | 0,943 |
| 8936 | 10,748 | 1,302 |
| 8742 | 8,022 | 0,815 |
| 7915 | 24,029 | 1,647 |
| **Медиана** | **8,670** | **0,943** |

Все 19 облачных выборочных запросов извлечения дали разбираемый список.
Медиана по ним 0,621 с; это выборка, а не проход всей книги частями.

Вся книга действительно передана одним запросом. Первый широкий запрос занял
29,590 с, сервер сообщил 449 751 входной токен. Ответ повторял список и оборвался
на 8192 выходных токенах (`done_reason:length`): результат непригоден.

Уточнённое задание — до 60 говорящих в сценах персонажей, объединение имён,
исключение титульного автора и лиц, лишь упомянутых в разговорах — завершилось
за **11,266 с**. Первый токен 7,522 с; сервер подтвердил 449 934 входных токена,
0 кэшированных, 1569 выходных, `done_reason:stop`. Получен законченный JSON с
60 строками. Это **ограниченный справочник**, не доказательство обнаружения
всех персонажей книги и не разметка всех реплик.

Даже здесь остались общие варианты вроде «князь», «генерал», «мать» и отдельная
строка «Иван Петрович» рядом с Птицыным. Такие обращения нельзя использовать
как глобальные уникальные ключи без контекста сцены.

Flash и Pro имеют заявленное окно 1M токенов:
[Flash](https://ollama.com/library/deepseek-v4.1-flash),
[Pro](https://ollama.com/library/deepseek-v4-pro/tags).
Вместимость входа не гарантирует правильность или полноту ответа.

Ожидаемые связи проверены вручную. Это небольшая проверка, не оценка точности

или нормализации схемы, хотя решение «разные люди» правильное.

## Практический вывод для концепта

На телефоне возможна разовая автономная подготовка книги частями. Текущая Gemma
E2B требует повторов, проверки формата и проверки связей имён; полный готовый
план голосов займёт больше измеренных 20 мин 53 с. Облачная модель заметно быстрее
и лучше прошла короткую проверку контекста, но её результат также надо проверять.

Справочник персонажей и определение говорящего в конкретной реплике — две
отдельные операции. Полезен предварительный разбор книги, затем обработка
текущей сцены с готовым справочником и стабильными `characterId → voiceId`.
Неподтверждённая личность, неизвестный пол или недопустимый ответ дают голос
автора. «Князь», «генерал» и местоимения разрешаются только внутри сцены.

Для Moon можно импортировать/выбрать EPUB в MyTTS, сохранить его SHA256 и
справочник, затем сопоставлять приходящий исходный текст с текстом этой книги.
Хэш сам по себе не сообщает, какую книгу открыл Moon: при неоднозначности нужно
явно выбранное пользователем произведение. Стандартный Android TTS не обещает
название книги, полный текст и позицию чтения:
[TextToSpeechService](https://developer.android.com/reference/android/speech/tts/TextToSpeechService).

## DeepSeek Pro: дополнительная проверка по просьбе пользователя

Каталог настроенного провайдера содержит `deepseek-v4-pro:0813`; именно эту
версию подтвердили ответы сервера. Режим размышления выключен, как у Flash.

Запрос со всей книгой без ограничения числа говорящих персонажей занял
**81,949 с**. Сервер подтвердил 449 984 входных токена, из них 449 983 кэшированных
(этот же запрос ранее был остановлен при повторной блокировке телефона).
Ответ вновь повторял имена и оборвался на 16 384 выходных токенах:
`done_reason:length`. Незаконченный JSON непригоден как готовый справочник.

Затем Pro получил **точно тот же текст и инструкцию до 60 персонажей**, что
успешный Flash. Время **37,096 с**; первый токен 25,673 с, 449 933 входных токена,
0 кэшированных, 2644 выходных, `done_reason:stop`. После снятия Markdown-обёртки
JSON разбирается, но содержит **116 строк**, вопреки лимиту 60. В 25 названиях
найдены точные повторы (каждое дважды), присутствуют Наполеон, Жозефина, Даву,
которых инструкция исключала как лица из рассказанных историй. Общие варианты
«князь»/«генерал» также сохранены вопреки инструкции.

Таким образом, обе облачные модели вмещают весь вход. В этих конкретных пробах
Pro не улучшил качество справочника и оказался медленнее Flash. Это не общий
рейтинг моделей: небольшой набор, без размышлений, без настройки промпта
отдельно под Pro. Поднимать только лимит вывода не решает повторение списка.

Рекомендуемый следующий шаг при будущей реализации — ограниченные задания по
главам/сценам, свидетельства связи имён с позицией в книге, затем проверяемое
объединение справочника. Полный текст можно использовать для проверки спорных
связей. Одна огромная выдача не доказала полного и надёжного результата.

Материалы измерений: `/tmp/mytts-character-benchmark-20261008/` — задания,
результаты JSONL, разбиение, нативные логи и ручные ожидаемые связи. В отчёте
нет ключей API.
