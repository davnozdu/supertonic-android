# База готовых звуков событий (sound bank)

5.0.6-beta78, code 322 (в beta74 было 391 клип, сейчас 678 видов). Продолжение `ambience-events-2026-10-28.md` и `ambience-second-pass-2026-10-28.md`.

## Что это

391 готовый клип событий, сделанный моделью один раз для всех книг: один клип на вид действия, 8 секунд
(`AmbienceBook.EVENT_SECONDS`), AAC 96 кбит/с, 44 100 Гц, стерео, −14 LUFS. Модель та же, что в приложении —
Stable Audio 3 Small SFX (`sm-sfx`, DiT w8a8) + декодер SAME-S, 8 шагов. Фон локаций в базу не входит: он делается
на телефоне, 30 секунд и в нескольких вариантах на место.

Список и промпты: `tools/sound_bank/sounds.json` (ключ вида, русская подсказка, английский промпт, seed).
Приложение видит ровно эти виды: `books/EventKinds.kt` содержит тот же набор ключей.

## Где лежит

Релиз GitHub `sound-bank-v1`: отдельными файлами (без архива) — `manifest.json` и `<вид>.m4a`,
https://github.com/davnozdu/supertonic-android/releases/tag/sound-bank-v1

## Как работает в приложении

1. «Фоновая музыка» → «База готовых звуков событий»: тумблер (по умолчанию включён) и кнопка «Скачать/Обновить
   список базы». Скачивается только `manifest.json` (кэш в `files/sound-bank/manifest.json`).
2. Когда книге нужен клип вида, приложение сначала ищет его в базе: если файла у телефона нет, качает ровно один
   файл `<вид>.m4a` (~100 КБ), сверяет sha256 из manifest и копирует в папку книги. Генерации ноль.
3. Чего в базе нет, создаётся для книги и дописывается в локальную базу телефона (`files/sound-bank/`), с пометкой
   «сделан для книги» в `index-local.json`. Следующая книга возьмёт этот звук уже бесплатно.
4. Второй проход разметки: вид, который есть в списке (= есть клип в базе), используется даже при одном упоминании;
   новый вид создаётся только при двух и более упоминаниях; одиночное неопознанное действие пропускается.

## Сборка базы (на ноутбуке)

    /tmp/mytts-sao/venv-sa3/bin/python sa3/optimized/tflite/scripts/sa3_tflite.py --dit sm-sfx --decoder same-s \
        --precision w8a8 --seconds 8 --steps 8 --seed <seed> --threads 5 --prompt "<промпт>" --out <вид>.wav
    # громкость двумя проходами: измерение loudnorm, затем кодирование
    ffmpeg -i <вид>.wav -af "loudnorm=I=-14:TP=-1.5:LRA=11:measured_I=...:linear=true" -c:a aac -b:a 96k -ar 44100 -ac 2 <вид>.m4a
    python3 tools/sound_bank/pack.py <каталог с m4a>   # manifest.json + sounds.db

Проверено: 391 из 391 клипов, длительность ровно 8.000 с, sha256 в manifest, суммарно 38,5 МБ.

## Сопоставление названий

Модель может назвать вид по-своему: `open_door`, `door_opening`, `slammed_door`. Поэтому ключ не сравнивается буквально:
`EventKinds.resolve` приводит название к канону (слова в нижнем регистре, синонимы сведены: open/opening/opened,
close/closing/shut, slam/slammed/banging, footsteps/step/walking, laugh/laughter, jingle/jingling…), порядок слов не
важен (`open_door` = `door_open`), затем допускается вхождение одного названия в другое (`hooves` ⊂ `horse_hooves`),
затем совпадение не меньше двух третей слов. При ничьей (`hooves` — это шаг, рысь или галоп?) вид не угадывается,
и решение принимает второй проход.

Второй ключ поиска — описание: если вида в базе нет, `SoundBank.find` сравнивает слова промпта книги со словами
описаний базы (и с именем вида). Найденный клип берётся без генерации. Проверено на 30 вариантах названий.

## Выгрузка и импорт

- «Выгрузить базу» — все клипы базы одним zip (`manifest.json` + `<вид>.m4a`) через системный выбор файла.
- «Импортировать базу» — тот же zip; приложение спрашивает «Заменить целиком» или «Слить». При слиянии одинаковые
  файлы (по sha256) пропускаются, другой звук того же вида не затирается; импортированные клипы помечаются
  `custom: true`, если такого вида нет в списке.

## Варианты на вид

У каждого вида не один клип, а два-три (разные seed), чтобы частое действие не звучало одним и тем же файлом.
Приложение выбирает вариант по виду и книге: внутри книги действие звучит одинаково (один клип на вид), а в
разных книгах — по-разному. GitHub допускает до 1000 вложений на релиз, поэтому варианты разложены по двум
релизам: `sound-bank-v1` (основной и второй) и `sound-bank-v1-more` (третий); manifest хранит полный адрес каждого.

## Наложение звуков

Два звука событий никогда не звучат одновременно: если предыдущий клип ещё играет, следующий момент пропускается
(`AmbiencePlayer.shotUntil`, проверка в момент запуска, а не при планировании).

## Что осталось

- Приложение с базой ещё не собрано в APK и не проверено на телефоне (CI проверяет только компиляцию и тесты).
- Загрузка базы на телефоне, копирование клипов из базы в книгу и рост базы — проверить на живой книге.
