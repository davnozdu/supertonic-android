# Готовый текст книги: чтение без нейросети

Версия формата: **2** (`version: 2` в `book.json`). Файлы версии 1 читаются как раньше — просто без готового текста.

## Что в файле

К обычным разделам (`sections`, `casts`, `fingerprints`, `replies`, `ambience`) добавился один:

```json
"prepared": {
  "algorithm": "fnv1a64-all",
  "texts": { "<hex отпечатка предложения>": "предложение с ударе́ниями, ё и пунктуацией" }
}
```

- Ключ — FNV-1a от **всех** букв предложения (не от первых 48, как `fingerprints`): так находятся и короткие реплики
  («— Да.»), а не только длинные предложения.
- Значение — то же предложение, но в том виде, в каком его читает движок: ударения U+0301, восстановленная ё,
  расставленная пунктуация.
- Предложение режется по `. ! ? …` вместе с пробелами после него (`PreparedText.pieces`), поэтому абзац
  собирается обратно байт в байт, вместе с переводами строк.

Размер: примерно как сам текст книги плюс 2–4 % на знаки ударения; архив книги сжимает его в 2–3 раза.

## Как это работает при чтении

1. `BookMatcher` узнаёт книгу и раздел по отпечаткам (как и раньше).
2. `LlmPreparation.preparedResult` ищет каждое предложение пришедшего текста в `prepared` книги.
   - Все предложения найдены и буквы совпали → текст берётся из файла, провайдер `книга`, запроса к LLM нет вообще;
     голоса — из разметки реплик книги (`replies`), тоже без сети.
   - Хотя бы одно предложение не найдено или буквы разошлись → фрагмент идёт обычным путём: облако (если оно
     настроено и есть сеть) или словари. Ничего не «залипает».
3. Проверка ударений облаком (`StressCheck`, «арбитр») для готового текста не запускается: он уже окончательный.
4. Очередь наперёд (читалки, которые просят текст заранее) получает готовый текст сразу — `submit()` создаёт
   готовую запись, рабочий поток LLM не просыпается.

Проверка «слова не изменились» — по буквам: `BookFingerprint.letters(готовое) == BookFingerprint.letters(исходное)`.
Это защита от чужого издания, испорченного файла или подменённого ответа.

## Как готовится

Галочка «Готовить текст с ударениями» на экране книг (и флаг `text` в очереди «Подготовить ночью») запускает шаг
`PreparedMarking`: абзацы книги уходят в облако пакетами по 2400 знаков тем же запросом, что и при чтении
(инструкция `stress`), ответ проверяется на дословность, предложения складываются в `prepared` и пишутся в файл
книги. Каждый пакет кэшируется по своему тексту, повторная подготовка ничего не пересчитывает.

## Проверено

Локальные тесты (`kotlin-jvm-quick-tests`, 7 случаев): нарезка предложений и обратная сборка, ключ без учёта
регистра/ё/ударений, сборка абзаца, отказ при неполном наборе и при чужих словах, короткие реплики, запись и
чтение раздела `prepared`, пустые входы.

Телефон (5.0.6-beta126, OnePlus CPH2745): маленькая книга «Тест готового текста» (EPUB, 2 раздела, 6 абзацев)
подготовлена с галочкой — в `book.json` 21 предложение с ударениями; при чтении в журнале только
`Готовый текст книги: LLM не нужна` и `provider=книга`, ни одного запроса к облаку и ни одной проверки арбитра.
Текст, которого нет в книге, ушёл обычным путём (словарь + облако), то есть резерв работает.
С выключенным Wi-Fi книга читалась так же — из файла.

## Что осталось

- «Умная книга» по-прежнему генерирует пересказы в момент запроса; в файл они не кладутся.
- Импорт `.mytts-book` версии 2 работает, экспорт кладёт `prepared` внутрь `book.json`; отдельного файла рядом
  с книгой больше нет.
