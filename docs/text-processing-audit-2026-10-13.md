# Аудит подготовки текста MyTTS: ударения, е/ё, пунктуация и имена

Дата: 13 октября 2026. Репозиторий `supertonic-android`, ветка `feature/model-selector`,
HEAD `f1564a34`, версия исходников `5.0.4-beta26`, code 201.
Это аудит исходников, а не утверждение о версии, установленной на телефоне.
При начале работы уже существовали два незакоммиченных отчёта; они не изменены.
Код приложения, настройки телефона, релизы и ключи не менялись.

## Основной вывод

Главная уязвимость редких имён и фамилий — не только отсутствие словарной записи.
Система **не отличает надёжную словарную метку Silero от догадки его акцентора**:
одиночная метка считается достаточной и может заменить метку LLM без арбитра.
Затем уже изменённое произношение запоминается как произношение имени в книге.
Гарантии единого правильного произношения персонажа во всех падежах сейчас нет.

С е/ё есть две независимые проблемы: неверная ё от LLM проходит структурную проверку
и исключает слово из голосования; последующее словарное восстановление ё способно
стереть явную метку книги/лексикона. Пунктуация защищена хуже слов: валидатор
позволяет удалить границы коротких предложений при включённом исправлении пунктуации.

Ниже «подтверждено» означает наблюдение на настоящих Kotlin-функциях или прямую
ветку исполнения кода. Это не измеренная частота ошибок в книгах и не оценка звучания.

## 1. Прослеженная цепочка

### Внешняя читалка и внутренний плеер

1. Android TTS получает исходный фрагмент. `LlmPreparation.submit` применяет
   `LexiconManager` до LLM, создаёт очередь, учитывает клиента и кэш результатов.
   [LlmPreparation.kt:68](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/LlmPreparation.kt#L68).
2. `prepareResult` отдаёт готовый результат или через 1500 мс возвращает исходный
   текст с `fallback=true`. При выключенной LLM — сразу автономная ветка.
   Читалки без очереди при `reader_direct_offline=true` переходят на словари,
   даже если облачный провайдер настроен. Первые фрагменты до распознавания режима
   могут пройти обычный путь. [LlmPreparation.kt:150](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/LlmPreparation.kt#L150).
3. Для LLM единицы, сокращения, даты и числа предварительно раскрываются:
   `RussianBookNormalizer` → `ForeignText.prepareNumbers`/`RussianNumberNormalizer`.
   Многословные числительные валидируются по исходным диапазонам и значению компонентов.
   [LlmPreparation.kt:565](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/LlmPreparation.kt#L565).
4. Далее облако и Gemma идут **в разном порядке**, описанном ниже.
5. `SupertonicTextToSpeechService` / `PlaybackService` используют `fallback` для
   `skipStress` и `skipDictionary`. Успешный LLM-результат не проходит повторно
   общую автономную расстановку ударений при синтезе.
   [SupertonicTextToSpeechService.kt:300](../app/src/main/java/com/brahmadeo/supertonic/tts/service/SupertonicTextToSpeechService.kt#L300),
   [PlaybackService.kt:452](../app/src/main/java/com/brahmadeo/supertonic/tts/service/PlaybackService.kt#L452).

### Облако

`LLM JSON + подсказки names` → **голосование и арбитр над ещё не валидированным ответом**
→ `PreparedTextValidator` → при отказе `PreparedTextRepair` и повторная валидация
→ `NameStress.learn` → `NameStress.fill` → `RussianNames.restore`
→ `YoRestore` → `MissingSpeechMarks` для оставшихся слов → кэш → синтез.

[LlmPreparation.kt:610](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/LlmPreparation.kt#L610),
[LlmPreparation.kt:662](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/LlmPreparation.kt#L662).

### Gemma

`LocalSpeechText` (протокол ударных заглавных/acute) → валидация/ремонт
→ заполнение уже известных имён (**Gemma не обучает NameStress**)
→ словарь имён → голосование Silero/RUAccent → два запроса Gemma-арбитру
→ `RussianYoPolicy` → заполнение недостающих меток → кэш → синтез.

Порядок правильнее облачного относительно проверки целостности, но после последующих
преобразований общей повторной валидации также нет.

### Автономная ветка

`BookTextSpacing` → пользовательские изменения пунктуации → `LexiconManager`
→ числа/сокращения → `RussianNames.restore` → импортированный словарь
→ `RussianStressVote.offline` → `RussianYoPolicy` → движок.

[TextNormalizer.kt:311](../app/src/main/java/com/brahmadeo/supertonic/tts/utils/TextNormalizer.kt#L311).

Важные особенности: словарь имён идёт раньше импортированного; уже поставленная
метка не меняется импортированным словарём. Если нужна личная коррекция фамилии,
её надёжнее делать через лексикон, но проблема последующего восстановления ё остаётся.
При выключенной локальной Silero `offline` возвращает текст сразу — RUAccent
самостоятельно в этой функции не голосует.

### Голосование

`RussianStressVote.silero` снимает acute с результата LLM и запускает
Silero → импортированный словарь → наложение словаря имён.
Это **составное мнение**, а не чистое независимое мнение нейросети Silero.

| Данные о слове | Реальное решение |
|---|---|
| В ответе уже ё, плюс или явная исходная метка | Не проверяется |
| RUAccent и составное мнение Silero совпали | Их метка окончательна, даже против LLM |
| Оба есть и различаются | Два порядка вариантов у арбитра |
| RUAccent-омограф ровно с двумя вариантами | Арбитр, кроме случая метки Silero вне обоих вариантов |
| Есть только одна словарная/модельная метка | Принимается без арбитра |
| Никто не дал метку | Остаётся LLM |
| RUAccent ещё не загружен | Метка LLM подставляется на место RUAccent |
| Арбитр противоречив/недоступен | Имя из словаря; часть неомографных меток Silero; затем LLM из двух вариантов; иначе первый |

[StressCheck.kt:82](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/StressCheck.kt#L82),
[RussianStressVote.kt:30](../app/src/main/java/com/brahmadeo/supertonic/tts/local/RussianStressVote.kt#L30).
Максимум 96 споров на пакет; остальные идут по резервному правилу.
Облачные два порядка запускаются параллельно; Gemma — последовательно.

## 2. Приоритетные находки

### F01 · Высокий · Догадка Silero о неизвестной фамилии заменяет LLM без арбитра

**Подтверждено A01.** LLM: `Залуме́ров`, Silero: `Залу́меров`, RUAccent: неизвестно.
Результат: `Залу́меров`, **0 споров**. Правильное произношение вымышленной фамилии
здесь не задано: дефект — отсутствие проверки различающихся мнений.

Причина: `r != null || s != null` в
[StressCheck.kt:110](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/StressCheck.kt#L110).
`LocalRussianStress` выдаёт акценторную догадку через argmax без порога уверенности
и не передаёт происхождение метки наружу.
[LocalRussianStress.kt:173](../app/src/main/java/com/brahmadeo/supertonic/tts/local/LocalRussianStress.kt#L173).

Следствие: редкая фамилия формально не становится «спорной». `RussianStressVote.tie`
до неё не доходит. Когда RUAccent ещё не готов, та же фамилия может попасть к
арбитру через `llmAsDictionary`; после загрузки поведение меняется.

Разбор исправления: отделить словарь/исключение/именной словарь/модельную догадку;
не объявлять единственную догадку акцентора окончательной для имени. Сравнивать её
с LLM и подтверждённым произношением персонажа. Два правильных словарных голоса
для обычных слов сохранять по согласованной схеме.

### F02 · Высокий · Ошибочная ё от LLM не проверяется

**Подтверждено A11–A12.** `рассерженный` → `рассержённый` принимается валидатором;
голосование пропускает слово даже при противоречащем мнении Silero/RUAccent.
Валидатор проверяет допустимость изменения е→ё, но не лингвистическую правильность.

[PreparedTextValidator.kt:66](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/PreparedTextValidator.kt#L66),
[StressCheck.kt:93](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/StressCheck.kt#L93).
Ограничения `ambiguousLocalYo` относятся к локальному дополнению/YoRestore,
а не к уже полученной ё от облака.

Разбор исправления: различать ё исходника и ё, добавленную обработчиком;
проверять новые сомнительные замены по контексту, не трогая авторскую ё.
Обязательные пары: все/всё, узнает/узнаёт, берет/берёт; отдельные отрицательные примеры.

### F03 · Высокий · Восстановление ё стирает явное ударение после валидатора

**Подтверждено A03–A04.** `Позвали Фе́дора.` → `Позвали Фёдора.`;
`че́рный` → `чёрный`. Это происходит даже если исходная метка принадлежала
книге/пользовательскому лексикону, а валидатор только что сохранил её.

`RussianNames.restore` заменяет слово при словарной ё независимо от существующего
acute; `YoRestore` удаляет acute при восстановлении ё.
[RussianNames.kt:92](../app/src/main/java/com/brahmadeo/supertonic/tts/utils/RussianNames.kt#L92),
[YoRestore.kt:12](../app/src/main/java/com/brahmadeo/supertonic/tts/utils/YoRestore.kt#L12).

В обычном слове исправление может улучшить произношение, но оно нарушает приоритет
явной коррекции пользователя. Метки LLM и исходные метки после слияния неразличимы.
Разбор исправления: протянуть защиту **по конкретным исходным вхождениям** через все
последующие преобразования; отдельно решить, допустимо ли исправлять LLM acute на ё.

### F04 · Высокий · Разрешено удалять границы предложений

**Подтверждено A10.** Валидатор принимает:

```text
Исходник: Да. Нет. Это было не раз.
Ответ:    Да Нет Это бы́ло не раз.
```

Слова, числа, переносы и кавычки защищены, а точки/запятые/тире/!? считаются свободно
редактируемыми. Промпт запрещает склеивать короткие предложения, но код это не проверяет.
[PreparedTextValidator.kt:8](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/PreparedTextValidator.kt#L8),
[LlmProviders.kt:48](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/LlmProviders.kt#L48).

Последствия: потеря интонации, смена контекста омографа, неверные границы чанков/пауз.
Разбор исправления: сохранять надёжные существующие границы; отдельно разрешать
контекстные добавления. Не запрещать всякое изменение пунктуации одним общим правилом.

### F05 · Средний · 63 омографа с 3–4 вариантами не получают обязательного арбитра

**Подтверждено A02 и реальной таблицей.** Ветка арбитра требует `variants.size == 2`.
Для `выходите` с вариантами 1,2,3 принимается одиночная метка Silero; без неё
сохраняется LLM. Также при двух вариантах метка Silero вне списка принимается
без проверки. [StressCheck.kt:104](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/StressCheck.kt#L104).

Разбор исправления: поддержать весь список вариантов либо явно определить правила
отбора; неизвестную метку вне вариантов считать поводом проверки, не окончательным решением.

### F06 · Высокий для фамилий · Запоминание закрепляет результат голосования

**Подтверждено порядком вызовов.** В облаке `stressVote` выполняется до `accept`;
`NameStress.learn(validated)` получает уже проголосованный результат.
Комментарий «learn from cloud models» не полностью описывает данные.
[LlmPreparation.kt:629](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/LlmPreparation.kt#L629),
[LlmPreparation.kt:665](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/LlmPreparation.kt#L665).

F01 поэтому способен попасть в память и следующий `names` prompt. Это не независимое
подтверждение произношения. Выученная подсказка добавляется раньше словарной и при
одинаковом bare-ключе выигрывает `distinctBy`; конфликт не помечается.
Метки, уже поставленные следующим ответом LLM, `fill` не исправляет (**A08**).

Разбор исправления: хранить происхождение/подтверждение, не обучаться на собственной
акценторной подстановке как на внешнем голосе; явно разрешать конфликт подсказок.

### F07 · Средний · Память имени не связывает падежи, начала предложений и разные книги

**Подтверждено A06–A07.** Выучено `Залу́меровым`; `Залумеров` и `Залумерову`
остаются неизвестными. Все появления в начале предложений исключены из обучения.
При этом заглавное слово внутри предложения считается именем без проверки сущности.

[NameStress.kt:40](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/NameStress.kt#L40).
Ключ — точная нижнерегистровая словоформа, не персонаж/лемма. Семейство падежей
не учитывается, ё/е в ключе NameStress не объединяются. При равном числе разных
меток нет явного решения «не уверен».

Граница памяти: смена клиента, новый текст приложения, смена настроек. Новая книга
в том же подключении внешней читалки сама по себе не сбрасывает NameStress.
Кэш текста также не содержит bookId/состояние выученных имён; результат для одинакового
текста может остаться прежним после уточнения произношения.
[LlmPreparation.kt:65](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/LlmPreparation.kt#L65),
[LlmTextCache.kt:5](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/LlmTextCache.kt#L5).

Разбор исправления: использовать подтверждённую сущность книги и её словоформы;
подвижное ударение не копировать механически по номеру гласной. Для неизвестной
читалкой книги нужна ограниченная сессия и понятная ручная коррекция.

### F08 · Средний · Узнавание Семёна портит последующие «семена»

**Подтверждено A09.** После `Я позвал Семена.` обработчик превращает
`Семена взошли весной.` в `Семёна взошли весной.`

Защита есть только для ключа `семена`, и она снимается после появления семейства
`семен` где-либо внутри предложения. Это не контекстная проверка текущей фразы.
[RussianNames.kt:16](../app/src/main/java/com/brahmadeo/supertonic/tts/utils/RussianNames.kt#L16).
Другие совпадения имени/обычного слова отдельной общей защиты не имеют.
Разбор исправления: учитывать контекст каждого упоминания и неоднозначность сущности.

### F09 · Средний · Дефисные записи имён частично недостижимы

В `names_ru.tsv` **27 051 словоформа**, включая **330 ключей с дефисом**.
Построитель допускает дефис, но regex в `RussianNames`/`NameStress` и `StressCheck`
разбивает слово по дефису: полный ключ не запрашивается.
[tools/names/build_names.py:19](../tools/names/build_names.py#L19),
[RussianNames.kt:14](../app/src/main/java/com/brahmadeo/supertonic/tts/utils/RussianNames.kt#L14).
Компоненты могут получить независимые метки, отличающиеся от записи полного имени.

Разбор исправления: единый токенизатор составных имён; определить правила одного/
нескольких ударений. Валидатор сейчас запрещает больше одного acute на токен,
но дефис разбивает имя на токены — эти ограничения надо согласовать.

### F10 · Средний · Заглавный регистр и отключение ё дают неполную обработку

**A05:** `ФЕДОРА` и `федора` словарь имён не обрабатывает; нужен initial capital
с хотя бы одной строчной буквой. Это объяснимо для обычных слов/аббревиатур,
но заголовки и фамилии капсом проходят мимо специального словаря.

**A16:** в автономной цепочке `RussianNames.restore` вызывается с обоими default=true,
затем `RussianYoPolicy(false)` превращает `Фёдора` обратно в `Федора`, **не добавляя
acute**. В облачном `restore(stress=true, yo=false)` получится `Федо́ра`.
Дальнейшая модель может исправить это своей догадкой, но цепочки уже различаются.
[TextNormalizer.kt:344](../app/src/main/java/com/brahmadeo/supertonic/tts/utils/TextNormalizer.kt#L344),
[RussianYoPolicy.kt:10](../app/src/main/java/com/brahmadeo/supertonic/tts/utils/RussianYoPolicy.kt#L10).

## 3. Имена и фамилии: что именно есть в нашей системе

### Постоянный словарь RussianNames

Источник — Wiktionary через Kaikki, given names/surnames/places и их словоформы;
не персональный реестр персонажей текущей книги.
При построении ключ е/ё объединяется; если есть ё-варианты, они получают предпочтение.
Разные ударения выбранного пула приводят к исключению ключа. Значит отсутствие
записи бывает и из-за неоднозначности, а не только нехватки материала.

В текущем asset есть `Мы́шкин`, `Мы́шкина`, `Фёдор`, `Фёдора`.
Нет точных ключей `иванов`, `иванова`, `иванову`, `рогожин`, `рогожина`, `дюран`, `дюпонт`.
Отсутствие односложных Жюль/Пьер само по себе не дефект ударения: acute им обычно не нужен.
Эта выборка не является полной статистикой всех имён/фамилий.

### Временная память NameStress

RAM на 2000 форм, частотный выбор номера ударной гласной. Не знает пола/персонажа/
фамильной семьи, не проверяет правильность произношения, не исправляет новую явную
метку. Это средство согласованности части ответов, а не подтверждённый словарь.

### Система персонажей и подготовки книги

`BookPreparation`, `NameCandidates`, `BookMorph`, cast, `BookMatcher`, `BookVoices`
связывают формы и назначают говорящего/голос. Словарь имён используется там как
источник **ключей** кандидатов. Эта система не передаёт `NameStress`/`StressCheck`
таблицу подтверждённых произношений персонажей.
[BookPreparation.kt:107](../app/src/main/java/com/brahmadeo/supertonic/tts/books/prepare/BookPreparation.kt#L107),
[LlmPreparation.kt:514](../app/src/main/java/com/brahmadeo/supertonic/tts/llm/LlmPreparation.kt#L514).

Поэтому корректная склейка `Рогожин/Рогожина/Рогожину` и правильный голос героя
не гарантируют правильного ударения. Нужен отдельный контракт произношения,
связанный с сущностью, а не переиспользование поля выбора голоса.

## 4. Последний участок: движки и пунктуация

| Движок | Обработка готовых меток |
|---|---|
| Tera | U+0301 → плюс перед гласной; при skipDictionary собственный словарь обходится. Типографское тире может стать запятой; многоточие → три точки; затем NFKD/tokenizer |
| Silero | Нижний регистр, acute → плюс; ё получает плюс, если его нет; фильтр алфавита. Интонационные typeIds и end-symbol corrections могут менять модельный конец фразы |
| Shtorm | Плюс → acute, нормализация пробелов; при отсутствии конечного знака добавляет точку в modelPrompt; деление ограничено длиной |
| Kokoro | Плюс → acute, нижний регистр, русские фонетические замены → native eSpeak → IPA; при отсутствии метки остаётся догадка native frontend |

**Отдельный подтверждённый дефект Kokoro (A14):** правило `-ого/-его → -ово/-ево`
применяется к любому слову после потери регистра. `Он приехал в То́го.` превращается
в `он приехал в то́во.` перед native G2P. Список исключений конечен, проверка
части речи/сущности отсутствует. Это не ошибка ударения, но дополнительный источник
неправильного произношения имён/топонимов. Нужны ограничения для прилагательных и
сохранение сведений об именах; проверять также иностранные фамилии с такими окончаниями.

Разбиение текста и паузы имеют отдельные эвристики сокращений/инициалов; арбитр
получает ограниченный контекст до 220 символов в каждую сторону плюс предыдущее
предложение, не полную историю героя. Точки в инициалах могут обрезать полезный
контекст. Это риск по коду; конкретная ошибка произношения не воспроизводилась.

## 5. Что уже защищено правильно

- Проверяется порядок и число слов, значения цифровых записей, ё исходника,
  положение/число acute, дефисы между словами, переносы, кавычки и скобки.
- При выключенном изменении пунктуации результат собирается на исходной пунктуации.
- Почти правильный ответ ремонтируется и вновь валидируется; большой пересказ отклоняется.
- Ударения книги/лексикона сохраняются на стадии валидатора; основные дырки ниже по цепочке.
- Два порядка вариантов уменьшают зависимость арбитра от позиции; противоречивый
  ответ не считается подтверждением.
- Текст/PCM кэш учитывает настройки и prepared text; при смене настроек есть инвалидация.
- Успешная общая подготовка защищена от повторного словаря Tera через skipDictionary.
- Прогноз ё неизвестного слова от акцентора Silero отключён; это полезная защита.
