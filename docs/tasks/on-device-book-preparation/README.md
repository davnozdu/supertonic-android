# Задание: подготовка книги прямо на телефоне + сворачиваемые карточки книг

Составлено 8 октября 2026 для LLM/разработчика, который будет писать код. Перед началом прочитать:
`/Users/davnozdu/Downloads/supertonic/AGENTS.md` (память проекта и правила работы с телефоном и релизами) и
`supertonic-android/docs/multivoice-books.md` (что уже сделано по голосам персонажей).

## Что хочет пользователь

1. В самом верху экрана «Книги с голосами персонажей» (`BooksActivity`) — блок **«Подготовить книгу»**:
   пользователь выбирает файл EPUB, MyTTS сам выполняет всю обработку (то, что сейчас делает компьютерный
   скрипт `mytts_book.py process`) через **облачную LLM**, и на выходе книга сразу появляется в списке
   (как после импорта `.mytts-book`); файл `.mytts-book` можно отдать кнопкой «Поделиться».
2. **Карточки книг сворачиваемые**: в списке видно только название (и автор/персонажей/разделов одной
   строкой); нажатие на книгу раскрывает её настройки — «Поделиться», «Удалить», голос автора, голоса
   прочих, персонажи с голосами и «Прослушать». Повторное нажатие сворачивает. (Сейчас кнопки видны всегда,
   а персонажи раскрываются отдельной кнопкой «Персонажи и голоса» — её заменить нажатием на карточку.)

Решения пользователя, которые нельзя менять без него:
- Скрипт делает механическую работу, LLM только сопоставляет формы. Сопоставление «железное»: сомнение —
  в «прочие». Правила общие для любых книг — никаких списков под конкретное произведение.
- Размышление LLM по умолчанию **включено**; по последующему уточнению пользователя нужен переключатель «Режим размышления» с пояснением о точности/скорости. Запросы — **строго по одному**.
- Ключи API никуда не записывать и не выводить (ни в логи, ни в файлы, ни в отчёты).

## Эталон: компьютерный скрипт

Логика уже написана и проверена на Python: публичный репозиторий https://github.com/davnozdu/mytts-books,
файл `mytts_book.py` (локально `/Users/davnozdu/Downloads/supertonic/mytts-books/mytts_book.py`; копия
этапа разработки — `supertonic-android/tools/characters/book_characters.py`). Перенести на Kotlin шаги:

| Шаг Python | Что делает | На телефоне |
|---|---|---|
| `read_epub` | OPF → spine, оглавление верхнего уровня (EPUB3 nav, иначе NCX), абзацы `p,h1–h6,li` без вложенных, якоря `file#id` разделяют разделы внутри файла | Jsoup (уже в зависимостях: `org.jsoup:jsoup:1.23.2`), `java.util.zip.ZipFile` |
| `Extractor` (`statistics`, `is_name`, `chain_key`, `possessive`, `attribute_speakers`) | кандидаты: цепочки слов с заглавной, обращения из `TITLES`, семьи, реплики в ремарках, род, соседство по абзацам | без pymorphy (см. ниже) |
| `detect_collection` | роман или сборник: у сборника <30 % главных имён встречаются в ≥¼ разделов | так же |
| `PROMPT`, `VERIFY`, `candidate_line`, `describe`, `verify_prompt` | запрос сопоставления и запрос проверки склеек | перенести тексты дословно |
| `build_cast` (`apply`) | строгая проверка ответа: каждый кандидат один раз; склейка только при `same` во второй проверке; род по надёжному источнику (глагол/отчество/обращение); обращение без имени — только если ≥80 % раз стоит перед именем этого персонажа; имя только из слов книги | так же |
| `voices` | на телефоне не нужен: голоса уже раздаёт `books/BookVoiceAssign` при чтении | — |
| `export` | `.mytts-book` v1 | собрать JSON того же формата и вызвать `BookLibrary.import(ctx, json)` |
| отпечатки | `sentence_fingerprints`, `letters`, FNV-1a 64 по первым 48 буквам | уже есть: `books/BookFingerprint.sentences()` (совпадает с Python, тест-векторы) |

Формат `.mytts-book` и алгоритм отпечатков: `docs/multivoice-books.md`, раздел «Формат обмена». Разбор и
проверка файла — `books/BookPackage.parse()` (строгий; если `import` не прошёл — значит JSON собран неверно).
`content_sha256` = SHA-256 от абзацев, нормализованных `BookFingerprint.letters()`, через `\n`;
`file_sha256` = SHA-256 байтов EPUB.

## Главная трудность: морфология без pymorphy

pymorphy3 на Android нет, порт его словаря (OpenCorpora, ~15 МБ) не делать. Заменить так (в Python
pymorphy использовался для четырёх вещей):

1. **Приведение формы к именительному** (Мышкина → Мышкин, Филипповны → Филипповна, Тоцкого → Тоцкий,
   Ганю → Ганя). Использовать статистику самой книги, как уже делает Python-функция `unknown_base`:
   отбросить падежное окончание и взять основу + вариант окончания, если такая форма **сама встречается в
   книге с заглавной** достаточно часто. Окончания и варианты расширить для прилагательных фамилий:
   окончания `ого, ому, ым, ом, ой, ую, ая, ей, ою` и т. д., варианты основ `"", о, а, я, ь, ий, ый, ой, ая`.
   Брать вариант с наибольшей частотой в книге. Имя в цепочке приводится по своему слову.
2. **Имя ли это вообще** («tagged» в Python). Источник — встроенный словарь `app/src/main/assets/names_ru.tsv`
   (27 051 форма имён/фамилий/названий из Викисловаря; `ключ\tформа с ударением`, ключ — нижний регистр, ё→е;
   загрузчик — `utils/RussianNames.load()`). Если слова нет в словаре, работают правила статистики:
   с заглавной внутри предложения ≥2 раз и со строчной не чаще.
3. **Род.** Главный источник уже не морфология, а глагол прошедшего времени в ремарке рядом с именем в
   именительном (`сказал/сказала`: окончание `ла` → ж., `л` → м.; для слов длиной ≥4, в ремарке после тире).
   Дальше: отчество по суффиксу (`-ович, -евич, -ич, -ыч` → м.; `-овна, -евна, -ична, -инична` → ж.),
   обращение (`князь/граф/генерал…` → м.; `княгиня/графиня/генеральша/…` → ж.), фамилия по суффиксу
   (`-ов, -ев, -ин, -ын, -ский, -цкий` → м.; `-ова, -ева, -ина, -ына, -ская, -цкая` → ж.). Имя по окончанию
   `-а/-я` **не** считать женским (Ганя, Коля, Илья — мужчины). Порядок источников как в `gender_source`.
4. **Фильтры не-имён:** нарицательные (со строчной чаще, чем с заглавной внутри предложения), междометия и
   служебные слова в начале предложения («Фу», «Ай», «Ну» — отсекаются правилом «в начале предложения
   только если слово хоть раз с заглавной внутри предложения или есть в словаре имён»), притяжательные
   («Зинина» при частой «Зина» — функция `possessive`), `NOT_PEOPLE`. Места (pymorphy `Geox`) не отсекаются —
   LLM отправит их в «прочие»; можно добавить простое правило «после в/во/на/из/под/за/к и т. п. чаще, чем без
   предлога» — по желанию, с проверкой, что не теряются персонажи.

Именительный падеж для реплик («— сказал князь», но не «сказал князю»): упоминание в именительном, если
каждое его слово совпадает со своей начальной формой из п. 1 (для обращений — со словом из `TITLES`).

**Обязательная проверка качества:** запустить Kotlin-извлечение на компьютере (чистый JVM, см. «Тесты») на
двух книгах и сравнить с Python (`mytts_book.py extract`): топ-40 кандидатов по упоминаниям, их ключи, род,
реплики. Книги: `~/Downloads/fedor_mihajlovich_dostoevskij-idiot-1488962523.epub` (роман, 4 раздела) и
`~/Downloads/darya_leonidovna_bobilyova-nochnoj_vzglyad-5da0bca3cbebf.epub` (сборник, 20 рассказов).
Ожидаемое: в «Идиоте» в топе князь, Рогожин, Настасья Филипповна, Аглая, Ганя (м.), Лебедев, Лизавета
Прокофьевна, Ипполит, Коля (м.), Евгений Павлович…; «Ночной взгляд» определяется как сборник. Расхождения
записать в отчёт. Без этого сравнения в бету не выпускать.

## LLM на телефоне

- Провайдер — тот облачный, что настроен в MyTTS (`LlmSettings.load(ctx)`): Ollama (`ollamaEndpoint`,
  `ollamaKey`, `ollamaModel`, по умолчанию Ollama Cloud) или Gemini (`geminiKey`, `geminiModel`). Если в
  режиме AUTO настроены оба — как в чтении (`preferGemini`). Локальная Gemma для этой задачи не годится.
- Вызов: `llm/LlmProviders.cloudRequest()` сейчас `private` — сделать `internal`. Он уже умеет оба
  провайдера, размышление (`c.copy(ollamaThinking = true, geminiThinking = true)` → `ThinkingPolicy`),
  схему ответа для Gemini, а Ollama Cloud схему не поддерживает (JSON только по инструкции). Нужно:
  - большой `deadlineMs` (основной запрос романа с размышлением ~2–3 мин; поставить, например, 10 мин) —
    `http()` использует его и как readTimeout;
  - большой лимит токенов (`tokens`): с размышлением 80000 (размышление входит в лимит; при `length` и
    пустом ответе — один повтор, как `chat()` в Python);
  - ответ читается с лимитом 512 КБ (`readNBytesCompat(512 * 1024)`) — для этой задачи хватает;
  - системная инструкция: передать пустую или короткую, а весь текст `PROMPT`/`VERIFY` — в `prompt`.
- Запросы по одному: основной, затем проверка склеек; в сборнике — по рассказам подряд.

## Выполнение и интерфейс

- Работа идёт минутами: запускать в фоне, не привязываясь к экрану. Использовать уже имеющийся
  `utils/ModelDownloadForeground.run(context) { … }` (foreground-сервис с wake lock, как у скачивания
  моделей) и отдельный объект-синглтон (например `books/BookPreparation`) с `StateFlow` состояния:
  этап (чтение EPUB → кандидаты → LLM N/M → проверка → сохранение), процент/счётчик запросов, ошибка, итог.
  Отмена — кнопкой «Остановить»; одновременно только одна подготовка.
- Выбор файла: `ActivityResultContracts.OpenDocument()` с типами `application/epub+zip` (и `*/*` на случай
  неверного типа у провайдера файлов). Скопировать EPUB во временный файл в `cacheDir`, после — удалить.
- Ограничения: файл EPUB до ~50 МБ; не держать всю книгу в памяти дольше нужного; ключ не логировать.
- Перед запуском показать, какой провайдер и модель будут использованы и что в облако уходит только список
  кандидатов с короткими примерами (не вся книга). Если облако не настроено — сообщение с подсказкой
  «настройки LLM».
- По завершении: `BookLibrary.import(ctx, json)`, затем то же, что после импорта (`changed()` в
  `BooksActivity`: `BookMatcher.forgetAll()`, `BookVoices.clear()`, `SpeechPreparationCache.clear()`);
  показать итог: «Книга «…»: персонажей N, разделов M, в «прочих» K» и (по желанию) список снятых проверкой
  склеек. Промежуточные данные (кандидаты, ответы) можно держать в `cacheDir/book-prep/<sha>/`, чтобы
  повторный запуск после обрыва не спрашивал заново уже полученные ответы (как `llm` в Python).
- Карточки: см. «Что хочет пользователь», п. 2. Компоненты: `CharacterVoices(...)` уже есть в
  `BooksActivity`, `VoiceRoleChoice` — `ui/VoiceRoleChoice.kt`, прослушивание — `llm/VoicePreview`.

## Тесты

Gradle-тесты локально не запускаются; используется чистый JVM-прогон Kotlin-файлов без Android (см.
`AGENTS.md`: компилятор `kotlin-compiler-embeddable 2.0.21` из `~/.gradle`, JDK
`/opt/homebrew/opt/openjdk@17`, заглушка `org.junit`). Поэтому код извлечения и проверки ответа писать
**без Android-зависимостей** (Jsoup и org.json можно: их jar подключаются к прогону; Jsoup jar —
скачать `org.jsoup:jsoup` той же версии с Maven Central в scratchpad).

Обязательные тесты:
- чтение EPUB обеих книг: число разделов/абзацев совпадает с Python (`«Идиот»: 4 раздела, 4577 абзацев`,
  `«Ночной взгляд»: 20 разделов, 2129 абзацев`);
- приведение форм: Мышкина→мышкин, Филипповны→филипповна, Тоцкого→тоцкий, Ганю→ганя (на статистике книги);
- род: «— сказал Ганя» → м. при словарном женском окончании;
- проверка ответа LLM (`CastCheck`): дубли, несуществующие номера, `verdict != same`, конфликт рода,
  обращение у нескольких персонажей, имя не из слов книги — как в `build_cast`;
- сборка JSON → `BookPackage.parse()` проходит; `content_sha256` и отпечатки совпадают с Python-файлом
  `tools/characters/samples/idiot.mytts-book` для той же книги.
