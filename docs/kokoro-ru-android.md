# Kokoro-RU v2 в MyTTS

Источник: https://huggingface.co/zaakirio/kokoro-ru
Закреплённая версия: d649c57b239b18c4c384378127cbf01dba039bc1.

## Пакет

Готовые, неизменённые ONNX Q8: общая model_quantized.onnx для Светы и Маши,
отдельная model_dima_quantized.onnx для Димы. Стиль голоса — float32 [510,256],
строка выбирается по длине IPA. Выход 24 кГц mono float32 → нормализованный PCM16.
Размер двух моделей, трёх голосов и данных: 278672735 байт (≈266 MiB).

Пакет зеркалируется в releases/tag/kokoro-ru-v2 нашего GitHub. Размеры и SHA-256
закреплены в app/src/main/assets/kokoro_manifest.json. Скачивание возобновляемое;
ZIP фонемизатора проверяется по списку файлов, размерам, SHA-256 и пути внутри
корневой папки. Удаление Kokoro не удаляет другие модели.

## Русский текст

Общий путь подготовки MyTTS выполняет LLM или автономную нормализацию/акцентор.
KokoroG2p переводит явные +/U+0301 в острое ударение eSpeak и не переустанавливает
его. Используются авторские acute-aware ru_dict и phondata, не системный словарь
eSpeak. Орфоэпическая подготовка и редукция гласных портированы из ru_g2p.py;
IPA mapping — из Misaki. Пунктуация возвращается в строку фонем после нативного
вызова, чтобы запятые, вопросы и восклицания сохранились в encoder input.

JNI содержит только фонемизатор, не аудиоплеер. Код eSpeak NG 1.52.0 закреплён
на 4870adfa25b1a32b4361592f1be8a40337c58d6c и собирается GitHub/NDK для ARM64.
Нативные имена защищены R8 и проверяются релизным gate. Android TTS, Share и
вставка используют общий SupertonicTTS dispatcher. Music, роли, кэш и иностранная
TTS применяются общими механизмами, без отдельного плеера Kokoro.

## Лимиты и память

Строка IPA делится по пробелам до 500 символов, вход [0,ids,0] укладывается
в 512 токенов; слова не режутся и не удаляются. Незнакомые фонемы отклоняются.
PCM ограничен 64 MiB на вызов. ORT — до 4 CPU-потоков, spinning выключен.
Две сессии загружаются по требованию и сохраняются для переключения голосов;
после 120 секунд без синтеза выгружаются, готовый PCM-кэш сохраняется.

## Проверки перед Android-сборкой

- Все upstream файлы сверены по LFS SHA-256 или Git blob SHA-1 и размеру.
- Фонемизатор собран отдельно для теста на компьютере (не APK). Авторские
  данные различают за́мок/замо́к, све́тло/светло́, де́ла/дела́, корректно передают ё.
- Оригинальные Q8 обеих моделей запущены ONNX Runtime CPU: все три голоса
  выдали конечный ненулевой WAV 24 кГц. Короткая фраза: 2675–2875 мс звука,
  1375–1472 мс синтеза, RTF≈0.51 на этом компьютере. Это не замер телефона.
- 26 JVM-тестов Kokoro/Tera/пробелов и 49 тестов ролей/кэша/громкости прошли.

Субъективное качество, плавность длинного чтения и скорость Android проверяются
на устройстве после GitHub-сборки. Авторский model card указывает OpenRAIL для
весов и Apache-2.0 для G2P; eSpeak NG GPL-3.0-or-later. NOTICE и документация
поставляются вместе с моделью.

## Релиз и установка · 5 октября 2026

Beta 4.9.2 (code 101, commit 0d039bf9) собрана и подписана на GitHub:
Android Release 37287522800 завершён успешно, APK опубликованы как prerelease.
ARM64 APK установлен через `adb install -r`; Android подтвердил code 101 /
versionName 5.0.0-beta4.9.2, прежняя подпись совместима.

Первый запуск нативной сборки выявил утечку C-only compat headers eSpeak в
C++ JNI include path; исправлено приватным include для C-библиотеки. Затем
проверка mapping ошибочно требовала записи каждого native-метода. Теперь
Kokoro JNI проверяется непосредственно в DEX всех релизных APK: класс,
точные имена, сигнатуры, native / instance access и отсутствие Java-кода.
Проверка прошла на пяти debug APK; APK без Kokoro и с переименованным
initialize отклонены. Релиз также прошёл эту проверку после R8.

По последнему указанию пользователя модель устанавливается для его собственного
прослушивания. На телефоне ещё не проводились синтез трёх голосов, измерение
RTF и диалог через Ollama: компьютерные проверки не выдаются за Android-тесты.
Предыдущая модель Tera сохранена в настройках; Kokoro пользователь выбирает
и скачивает отдельной кнопкой (≈266 MiB) для теста. USB screen-on восстановлен
в 0, громкость не менялась (43). Дальнейшая проверка без звука доступна через
SpeechDiagnosticsActivity / voicePreviewProbe и multiVoiceProbe.

## Проверка скорости и CPU · Beta 4.10

Пользователь подтвердил хорошее звучание, но долгую генерацию первого фрагмента.
Чтение остановлено, повторные беззвучные проверки разрешены. На Beta 4.9.2:

- Все три voicePreview прошли. 71 знак / 82 фонемы, speed=1.1: Света 4601 мс
  на 4750 мс PCM (холодная сессия), Маша 3557/4750 мс (та же сессия), Дима
  4373/4700 мс (отдельная холодная сессия). LLM в preview обходится.
- Общая проверка с Ollama прошла: допустимые ударения доходят до Kokoro,
  skipDictionary=true, русский и смешанный иностранный текст дают WAV 24 кГц.
  Повторный PCM отдан из кэша; общий повтор 702 мс вместо 9296 мс.
- Отдельный прогон трёх голосов: wall 12,38 с, process CPU 16,64 с; в среднем
  134,4% одного ядра (16,8% из восьми), пик по интервалам около 207,3%
  (25,9% из восьми). Пик RSS всего процесса 997,7 MiB. Это не PSS/размер весов
  и не прямое измерение батареи. Источник: /proc/stat, CLK_TCK и PAGE_SIZE
  устройства; синтетические preview, без LLM/музыки.
- При автоблокировке OnePlus заморозил диагностический процесс: один прогон
  исказился до 87 секунд и истёк по таймауту. Повтор после увеличения таймаута
  экрана прошёл. Зависший прогон не используется для оценки скорости модели.

Профиль ORT на компьютере показал большую долю ConvInteger в Q8 decoder.
Оригинальные русские FP32 ONNX закреплённой версии, без изменений/конвертации,
проверены по upstream SHA-256 и выложены в наш tag kokoro-ru-v2: model.onnx,
model_dima.onnx, вместе 651268904 байта (≈622 MiB). На том же компьютере,
фразе и четырёх потоках: Q8 2499–2517 мс, FP32 1036–1069 мс. Это основание
для проверки на телефоне, не обещание такого же ускорения Android.

Beta 4.10 добавляет отдельное скачивание и выбор «Компактный Q8» / «Полная
точность», не удаляя Q8. Полный пакет используется по умолчанию только после
проверенной установки; выбор пользователя сохраняется. Переключение учитывается
в ключе PCM-кэша и лениво пересоздаёт сессию перед следующим синтезом. Оба
варианта используют те же русский G2P, LLM, голоса, кэш и таймер выгрузки.
В логах разделены g2pMs/loadMs/inferenceMs. kokoroBenchmark сравнивает холодный
и повторный синтез Q8/FP32, CPU и PSS при 2/4/6 потоках без воспроизведения.
Диагностическое окно теперь удерживает экран включённым. Android-проверка
полного пакета выполняется после GitHub-сборки.
