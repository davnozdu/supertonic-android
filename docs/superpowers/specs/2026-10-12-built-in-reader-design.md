# Встроенная читалка MyTTS — проект (12 октября 2026)

Статус: черновик на согласование. Код не писался.

## Зачем

Сейчас MyTTS озвучивает книги через чужие читалки (Moon+ Reader, Readest) по протоколу Android TTS. Читалка решает,
сколько текста и когда отдать, поэтому приходится угадывать: заранее готовить то, что Moon+ поставил в очередь, узнавать
книгу и главу по отпечаткам абзацев, отдельно учитывать Readest, который даёт по одному предложению (паузы, beta15
«без ожидания LLM»). Цель — читать и слушать прямо в MyTTS: приложение само видит весь текст главы и готовит его так, как
задумано (LLM пакетами вперёд, роли и голоса персонажей, ударения с арбитром, многоязычие, фоновая музыка), без
посредников и без потери качества ради плавности.

Решение пользователя: готовый движок читалки берём у Readest, Readest и KOReader целиком не встраиваем.

## Что берём

**foliate-js** (github.com/johnfactotum/foliate-js, MIT) — движок Readest (у Readest форк `readest/foliate-js`, тоже MIT)
и GNOME Foliate. Чистый JavaScript в WebView, без сборки:

- форматы: EPUB 2/3, FB2 и FB2.ZIP, MOBI/AZW3/KF8, CBZ; PDF через pdf.js — не в первой версии (≈ +5 МБ);
- `view.js` — элемент `<foliate-view>`: открыть книгу, листать (страницы или прокрутка), оглавление, `goTo`, CFI-позиции,
  событие `relocate` с долей прочитанного;
- `tts.js` + `text-walker.js` — блоки текста главы, предложения/слова с метками, язык каждого элемента (`xml:lang`);
- `overlayer.js` — подсветка диапазонов;
- `epub.js` → `MediaOverlay` — воспроизведение EPUB 3 Media Overlays (SMIL: текст + аудио).

Лицензии: MIT совместима с GPL-3.0 MyTTS; копия `LICENSE` и коммит рядом с файлами. Код интерфейса Readest (AGPL) не
копируем — интерфейс пишем свой на Compose. Версия: upstream, закреплённый коммит (сейчас `78914aef`); исправления из
форка Readest переносим точечно при необходимости.

KOReader не подходит: приложение на Lua/C со своим рендером и интерфейсом, не встраивается как компонент; AGPL.
Readium Kotlin Toolkit (BSD) рассматривался: нативный Kotlin, но без FB2 — у пользователя много FB2.

## Архитектура

```
ReaderActivity (Compose)
 ├─ WebView: assets/reader/  ← foliate-js + reader-bridge.js (наш)
 │     ⇅ JS-мост (@JavascriptInterface / evaluateJavascript), только локальные ресурсы
 ├─ ReaderLibrary (books.db, новая таблица)     — книги, место, настройки книги
 └─ ReaderSpeech  → PlaybackService (наш плеер) → конвейер синтеза (LlmPreparation, SupertonicTTS, музыка)
```

### 1. Загрузка и безопасность
- `WebViewAssetLoader`: `https://appassets.androidplatform.net/reader/…` — foliate-js и мост из assets; книга —
  через отдельный обработчик пути `/book/<id>`, который отдаёт файл из папки приложения потоком (без копии в память JS).
- JavaScript только для своих ресурсов; сеть в WebView запрещена (`blockNetworkLoads`), внешние ссылки книги открываются
  системным браузером по подтверждению. Скрипты книги не исполняются: iframe главы без `allow-scripts` (проверить на этапе 1, как это сделано в foliate-js/Readest).

### 2. Библиотека
- Импорт: «Открыть книгу» (системный выбор файла), «Открыть с помощью» / «Поделиться» из файлового менеджера. Файл
  копируется в `files/library/<sha256>.<ext>`; повторный импорт того же файла не дублирует книгу.
- Таблица `reader_books` в существующей `books.db`: id, sha256, формат, название, автор, обложка (миниатюра в файле),
  CFI места чтения, доля прочитанного, время открытия, настройки книги (шрифт, тема, поля). Метаданные отдаёт foliate-js
  (`book.metadata`) при первом открытии.
- Связь с голосами персонажей: если для текста книги есть импортированный `.mytts-book` (совпадение отпечатков абзацев,
  как сейчас), книга получает его персонажей и голоса; выбор раздела — точный, по главе, без угадывания.
- Экран «Книги» объединяет обе части: читаемые книги и подготовленные `.mytts-book`.

### 3. Экран чтения
- Сверху: название, оглавление, поиск по книге (foliate `search.js`). Снизу: ползунок прогресса, ◀◀ / ▶ / ▶▶ по
  предложениям, скорость, голос, таймер сна. Тап по краям — листание, по центру — показать/скрыть панели.
- Внешний вид: размер шрифта, межстрочный интервал, поля, тема (светлая / сепия / тёмная), страницы или прокрутка —
  через `renderer.setStyles` и атрибуты `foliate-paginator`.
- «Читать отсюда»: долгий тап по предложению — начать озвучку с него.

### 4. Озвучка (главное)
`reader-bridge.js` (наш, поверх `text-walker.js` и `Intl.Segmenter`) для текущей главы:
1. обходит блоки текста (`p`, `h1…`, `li`, `blockquote`…), режет их на предложения, каждому даёт id и запоминает его
   DOM-диапазон; язык — из `xml:lang`/`lang` элемента (многоязычие без угадывания, где книга размечена);
2. отдаёт Kotlin всю главу сразу списком `{id, text, lang, blockId}` (абзацы — группы предложений);
3. по команде `highlight(id)` подсвечивает предложение и при необходимости листает страницу.

`ReaderSpeech` (Kotlin):
- передаёт абзацы главы в `PlaybackService` новым вызовом `playSegments(contentId, segmentsJson, startId)` — плеер уже
  умеет держать буфер звука, музыку, уведомление, медиакнопки, звонки и таймер сна;
- LLM готовит абзацы вперёд пакетами, как для Moon+ (книга и глава известны точно — роли и персонажи с первого абзаца);
- плеер сообщает `onSegment(contentId, id)` в момент **воспроизведения** (по позиции AudioTrack, не по окончанию
  синтеза) → `highlight(id)`; место чтения сохраняется по последнему прозвучавшему предложению;
- конец главы — следующая глава подаётся заранее, переход без паузы; пауза / стоп / ▶▶ — те же команды плеера.

Готовый класс `TTS` из foliate-js (SSML по одному блоку) напрямую не используем: он рассчитан на читалку, которая ждёт конца
блока, а нам нужен текст вперёд. Его разбор на блоки и метки повторяем в мосте.

### 5. Книги с аудио (EPUB 3 Media Overlays)
- **Воспроизведение** готовых книг со звуком: `MediaOverlay` из foliate-js играет `<audio>` в WebView и подсвечивает
  текст; наш интерфейс управляет им теми же кнопками. Синтез MyTTS в этом режиме не участвует.
- **Экспорт** «Озвучить книгу в EPUB со звуком»: синтез глав в фоне (сервис, как подготовка книги), аудио в AAC (`.m4a`,
  MediaCodec), копия книги с id на каждом предложении + SMIL с временами + `media:duration` в OPF. Файл открывают
  Readest, Thorium, Apple Books. FB2 при экспорте превращается в EPUB.

### 6. Внешние читалки
Движок MyTTS для Moon+ / Readest остаётся без изменений.

## Этапы

1. **Читалка.** Импорт EPUB/FB2/MOBI, библиотека, открытие, листание, оглавление, место чтения, внешний вид.
2. **Озвучка в читалке.** Мост, `playSegments`, подсветка по воспроизведению, LLM вперёд, персонажи по главе, музыка,
   «читать отсюда», переход между главами.
3. **Книги с аудио.** Воспроизведение Media Overlays; затем экспорт.

Каждый этап — отдельные бета-версии; Moon+ работает всё время.

## Проверка
- JVM-тесты: разбор списка сегментов, библиотека (импорт, дубликаты, место чтения), склейка абзацев для LLM.
- Телефон (XML-дамп интерфейса, без скриншотов; логи): «Идиот» EPUB, «Ночной взгляд» FB2, книга с `xml:lang`-вставками.
  Замеры: время до первого звука, паузы между предложениями и главами, совпадение подсветки со звуком, память
  (WebView + синтез), сохранение места после перезапуска.
- Регрессия Moon+: прежние пробы ударений/озвучки.

## Риски и открытые вопросы
- WebView на телефоне (Chromium 13x) поддерживает ES-модули и `Intl.Segmenter` — проверить на CPH2745 в этапе 1.
- Большие FB2 foliate-js разбирает целиком в JS — замерить память на 3–5 МБ FB2.
- Подсветка «по воспроизведению» требует, чтобы плеер помечал пакеты звука id предложения — доработка `PlaybackService`.
- Размер APK: foliate-js без pdf.js ≈ 0,5 МБ.
- Нужно ли редактирование (заметки, выделения, словарь)? Предлагается не в первой версии.
- Синхронизация места с Moon+/Readest — не планируется.
