# MyTTS 5.0 Beta 4.6: повторное «Поделиться»

4 октября 2026 года. Итоговый код `f71f3b34`, тег `v5.0.0-beta4.6`.
GitHub CI и Android Release завершились успешно. Подписанный ARM64 APK
установлен поверх предыдущей версии: versionCode 96, versionName 5.0.0-beta4.6.
Релиз опубликован как prerelease.

## Причины и исправления

1. PlaybackService при регистрации слушателя сразу отдавал прогресс прежнего
   чтения. PlaybackActivity брала last_text из SharedPreferences и заменяла
   им только что полученную статью ещё до запуска синтеза. Теперь callback
   содержит SHA-256 текста; новый запрос ждёт подтверждения собственного
   текста, старые события и несовпадающее сохранённое состояние отклоняются.
   После подтверждения разрешены переходы на следующие части статьи.
2. Повторный запуск из другой задачи Android мог возвратить уже открытый
   плеер без доставки нового запроса корневому экрану singleTop.
   MainActivity использует singleTask и обрабатывает onNewIntent;
   предыдущий экран плеера освобождается при приёме новой статьи.
3. Новый Share останавливает прежнее чтение до загрузки. Пустой запрос и
   ошибка загрузки не возобновляют старую статью. Учтены EXTRA_TEXT,
   EXTRA_HTML_TEXT, текст/URL ClipData и URI самого Intent. Короткий заголовок
   не скрывает URL из другого поля; длинный выделенный текст сохраняется.
4. Каналы панели и плеера имеют повышенный приоритет, уведомления ongoing.
   Звук/вибрация выключены; явно изменённая пользователем важность старого
   канала сохраняется. Место в общем списке определяет Android/прошивка.

## Проверки

- 69 локальных JVM-тестов прошли, включая новую защиту от старых callbacks,
  приём заголовка с URL в другом поле, продолжения, голоса и кэш.
- Из HTML [статьи Meduza](https://meduza.io/feature/2026/10/04/kak-dumaete-esli-podsadit-chelovecheskiy-mozg-drugomu-zhivotnomu-ono-stanet-umnee)
  выделены 22111 знаков / 49 абзацев; не попали меню, блок помощи, рекомендации
  о психоделиках и кнопка «Читать дальше». Это дополнительная статья для проверки,
  точная исходная ссылка пользователя не была предоставлена.
- В Beta 4.6 на телефоне отправлены два синтетических ACTION_SEND подряд
  обычным am start, без CLEAR_TOP/SINGLE_TOP в команде. Первый запрос: 114
  знаков, contentId `07004b11bd92`; второй: 95, `43be18bda2a3`.
  Плеер получил второй текст; SharedPreferences содержат вторую контрольную
  запись, первой там нет. Проверка выполнена с нулевой громкостью.
- Передана недоступная ссылка `http://127.0.0.1:9/missing-article`.
  По логам запрос принят; нового запуска старого текста после него нет.
  Сообщение диалога этой ошибки отдельно не подтверждено по UI.
- На телефоне уведомление 5411 имеет importance=4,
  ONGOING_EVENT | ONLY_ALERT_ONCE, sound=null, vibration=false.
- Громкость возвращена к актуальному значению 53, настройка USB stay-awake
  к 0, чтение остановлено. Длинная статья не проигрывалась целиком;
  субъективное прослушивание выполняет пользователь.

Отличие от повреждения аудиокэша: неверный текст попадал в новый запрос
синтеза из состояния плеера. Очистка кэша не требуется для этого исправления.
