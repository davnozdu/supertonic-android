## Совместимость с рабочими файлами на телефоне

Эталоны прочитаны из `/sdcard/Download/idiot.mytts-book` и `nochnoj_vzglyad.mytts-book`, исходники на телефоне не изменялись. `BookPackage.parse()` принимает оба. При новой механической подготовке **точно совпали** SHA-256 EPUB, `content_sha256`, все разделы и все отпечатки: **11345** у романа, **4642** у сборника. Экспорт нового плана через тот же строгий парсер также прошёл.

Рабочий роман содержит 28 персонажей, сборник — 50. Эти числа получены после облачного сопоставления, проверки и компьютерной раздачи голосов. Kotlin не обязан воспроизводить состав побайтно при новых ответах LLM; на телефоне раздача голосов выполняется отдельно штатным `BookVoiceAssign`. Ниже проверяется извлечение, а полный облачный прогон отмечается отдельно.

## Расхождения и границы проверки

- Главные ключи романа совпадают: князь, Рогожин, Настасья Филипповна, Аглая, Ганя, Лебедев, Лизавета Прокофьевна, Ипполит, Коля, Евгений Павлович. Ганя/Коля — мужские по глаголам ремарок.
- Приведение на статистике романа: Мышкина→мышкин, Филипповны→филипповна, Тоцкого→тоцкий, Ганю→ганя. Добавлены окончания имён на -ей: Сергея→сергей.
- Без pymorphy количество реплик несколько меньше: нужны именительная форма и глагол прошедшего времени перед названным говорящим. Не выдумываются реплики или женский род по окончанию -а/-я. Если надёжного рода нет, остаётся `?`, окончательное сопоставление делает LLM.
- Статистика объединяет некоторые падежи, которые Python разделял (например Тоцкий). Для неизвестных редких форм нормализация может остаться неполной; они отправляются отдельными кандидатами.
- Места Павловск/Петербург остаются кандидатами до LLM. Семьи определяются по общим суффиксам. Это намеренная замена морфологического фильтра согласно заданию, без списка персонажей конкретной книги.
- Строгая проверка не принимает склейки без единственного `same`, при конфликте надёжного рода или неоднозначном обращении. Несуществующие/повторные кандидаты, выдуманные имена, отсутствие проверки и повреждённый JSON покрыты JVM-тестами.

Рабочие законченные пакеты не затронуты. Kotlin всегда проверяет наличие ответа проверки отдельно, включая хеш её промпта.

## Проверка на телефоне

На 5.0.4-beta4/code179 установленной поверх предыдущей версии выполнен полный облачный прогон «Ночного взгляда»: Ollama / deepseek-v4.1-flash, размышление включено. Начало 13:03:58, импорт в базу 13:18:46 — около 14 минут 48 секунд. В кэше 20 основных ответов и 12 ответов проверки склеек. Работа продолжалась после ухода с экрана и при погашенном экране; во время обработки подтверждены foreground-сервис и `PARTIAL_WAKE_LOCK MyTTS:BookPreparation`. После импорта сервис завершился.

В базе книга с 20 разделами и 4642 отпечатками; `book`, `content_sha256` и все отпечатки точно совпадают с эталоном из Downloads. Это проверка формата/узнавания текста, не доказательство одинаковых решений LLM. Новый пакет хранит 112 подтверждённых персонажей, включая второстепенных; Python после `voices` исключает «прочих» из экспорта и оставляет 50. Из новых 112 порог штатной автоматической раздачи (≥2 реплики либо ≥30 упоминаний, известный пол) проходят 49. Например, Катя в s4 имеет одну обнаруженную ремарку вместо двух в Python и автоматически отдельный голос не получает. Встречаются разные отображаемые формы («Санек»/«Санька», «Изольда Марковну»/«Изольда Марковна»); побайтное равенство составов не заявляется.

XML интерфейса подтвердил переключение размышления и подписи о точности/скорости и времени обработки. Системный timeout возвращён к исходным 30000 мс, stay_on=0, громкость не менялась. Отмена/повтор после обрыва проверены отдельным runtime-прогоном; принудительное убийство процесса во время реального облачного прогона не выполнялось.

## FB2 и FB2.ZIP

В 5.0.4-beta5 добавлен общий загрузчик по содержимому файла: EPUB, FB2 либо ZIP с единственным FB2. XML учитывает объявленную кодировку и BOM; поддержка CP1251/UTF-16 проверена. Заголовки, абзацы и строки стихов сохраняют порядок; отдельные тела примечаний/комментариев и бинарные картинки не становятся текстом книги. Вложенные главы остаются внутри раздела; безымянная общая оболочка сборника раскрывается.

Для проверки без разницы изданий оба исходных EPUB механически преобразованы в FB2. Kotlin получил те же 4/20 разделов, 4577/2129 абзацев, `content_sha256`, отпечатки и ключи/счётчики кандидатов. Изменяется SHA-256 исходного файла; формат `.mytts-book` v1 общий. Для сторонних EPUB/FB2 того же названия равенство текста не гарантировано.

Runtime-прогон также подтвердил удаление оставшейся после обрыва временной копии исходника без удаления кэшированных ответов и посторонних файлов.

### Итог проверки beta5 на устройстве

Release37768674284 и CI37768672277 успешны; v5.0.4-beta5/code180 установлена поверх. Синтетический FB2 (размышление ON) и его FB2.ZIP (OFF) отдельно выбраны через системный файловый диалог и прошли облако/импорт. В обоих случаях два персонажа (Алексей m, Мария f), два раздела; Николай из тела примечаний не попал в кандидаты. ZIP заменил тот же текст, а не создал дубликат книги. Размышление возвращено ON.

Обычный Android TTS-клиент отправил три исходных абзаца «Ночного взгляда» в `synthesizeToFile` без preview-флага: 3/3 PCM-файла готовы, интерфейс MyTTS показал «Ночной взгляд», раздел «Старшая сестра». Это реальный путь узнавания подготовленного на телефоне пакета; звук не воспроизводился, слуховая точность назначения говорящих отдельно не оценивалась.

Через XML проверены раскрытие/сворачивание карточки, появление/скрытие действий. «Поделиться» создала `Ночной_взгляд.mytts-book`; выгруженный файл точно равен сохранённому JSON, адресат не выбирался. Тестовая книга удалена через интерфейс; временные клиент/вход/FB2/ZIP/XML удалены. На устройстве остались пользовательские «Идиот» и подготовленный «Ночной взгляд». Временный timeout возвращён с 1800000 к исходным 30000 мс; последующее чтение показало 15000 (изменено вне наших действий, оставлено). stay_on=0, громкость не менялась, диагностический logcat не запускался.
